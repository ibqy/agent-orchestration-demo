# 推理模式 —— 学习总结

> 结论先行：三种模式不是替代关系，是**按任务形状选择**。生产最常用的是 ReAct + Plan 混合。

## 三种模式对比

| 维度 | ReAct | Plan-and-Solve | Self-Reflection |
|------|-------|---------------|-----------------|
| 决策时机 | 每步现想 | 开局一次规划 | 执行后回看 |
| 适用 | 未知开放式问题 | 步骤固定的流程 | 对准确性敏感 |
| token 成本 | 低 | 中 | 高（多一轮 LLM）|
| 失败模式 | 中途跑偏 | 初始规划想当然 | 反思标准漂移 |

## 我的三个理解变化

### 1. ReAct 的关键是 Observation 回填

以前以为 ReAct 就是"循环调工具"，写了 [ReActAgent](../src/main/java/com/xb/agent/reasoning/ReActAgent.java) 才发现：**Observation 必须显式拼回上下文**，否则模型不知道上一步发生了什么，会重复调用。核心就这几行：

```java
String observation = toolInvoker.invoke(action.getToolName(), action.getToolArgs());
context.append("OBSERVATION: ").append(observation).append("\n\n");
```

### 2. Plan-and-Solve 必须 Re-Plan

[PlanAndSolveAgent](../src/main/java/com/xb/agent/reasoning/PlanAndSolveAgent.java) 踩过最大的坑：初始规划执行到第 3 步发现第 1 步理解错了，后面全错。解法是每步执行完做一次校验，偏差时让 LLM 重新输出修正后的完整计划，而不是硬着头皮执行完。

### 3. Self-Reflection 用装饰器而不是继承

[SelfReflectionAgent](../src/main/java/com/xb/agent/reasoning/SelfReflectionAgent.java) 包住任意 ReasoningAgent（组合优于继承）：

```java
new SelfReflectionAgent(new ReActAgent(...), model, 2)
```

反思 prompt 独立于主 prompt 的另一个好处：反思标准可以单独迭代，不污染主流程。

## 解析容错（被低估的部分）

[ActionParser](../src/main/java/com/xb/agent/reasoning/ActionParser.java) 占了 reasoning 包近三分之一的代码。LLM 输出格式永远不可靠：多换行、JSON 嵌套错误、关键字的 CasE 大小写。策略：
- 找不到 ACTION/ANSWER 关键字 → 整段当 THOUGHT，喂回格式提示
- JSON 提取用括号配对而不是正则
- 解析失败返回 `ofRetry` 而不是抛异常

## 模式选择速查

- 问题未知、需要探索 → ReAct
- 流程明确（工单/报告类）→ Plan-and-Solve
- 数据准确性关键（查询/计算类）→ ReAct 外面套 Self-Reflection
