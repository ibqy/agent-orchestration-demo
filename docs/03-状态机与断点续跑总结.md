# 状态机与断点续跑 —— 学习总结

> 结论先行：这是整个项目最值钱的部分。**任务快照 + 状态机 = 服务重启任务不丢**。

## 状态模型

```
INIT → PLANNING → RUNNING → REVIEW → SUCCESS
                    ↑          ↓
                    └─(REJECT)─┘
                    ↓
              WAIT_HUMAN →(confirm)→ RUNNING
                    ↓(abort)
                  FAILED
```

7 状态 9 事件，定义在 [AgentState](../src/main/java/com/xb/agent/state/AgentState.java) / [AgentEvent](../src/main/java/com/xb/agent/state/AgentEvent.java)。

## 为什么用状态机而不是 if-else

以前用 `if (status.equals(RUNNING) && event.equals(...))` 判断，漏掉一个分支就出灵异 bug。状态机把"什么状态下允许什么"**显式化**，非法流转直接拒绝：

[TaskRunner.transitionTarget](../src/main/java/com/xb/agent/state/TaskRunner.java) 用 switch 表达式穷举 9 个事件，非法组合返回 null 拒绝。Spring Statemachine 的 DSL 配置在 [StateMachineConfig](../src/main/java/com/xb/agent/state/StateMachineConfig.java)。

## 快照设计的反推法

[TaskSnapshot](../src/main/java/com/xb/agent/state/TaskSnapshot.java) 字段不是抄来的，是反推的：**"服务重启后，我要从哪里继续？"**

| 字段 | 为什么必须有 |
|------|-------------|
| planJson | 计划重放（哪些子任务没跑）|
| completedSubTaskIds | 断点续跑跳过已完成的 |
| steps（轨迹）| 回放调试 + 审计 |
| tokenUsed | 重启后预算继续计数 |

**落一个字段，重启后就恢复不回来。**

## 持久化时机：每次流转立即落盘

[TaskRunner.fireEvent](../src/main/java/com/xb/agent/state/TaskRunner.java)：状态变更 → 立即 `snapshotStore.save()`。别攒批——服务随时可能挂。

[SnapshotStore](../src/main/java/com/xb/agent/state/SnapshotStore.java) 两个取舍：
- TTL 7 天：任务快照不是永久数据，过期自动清理省内存
- 保存失败只记日志不抛异常：快照是旁路，不能拖垮主流程（生产要加告警）

## HITL（人工介入）实现

高危工具触发 `NEED_HUMAN` 事件 → RUNNING → WAIT_HUMAN，人工确认走 `HUMAN_CONFIRM` 恢复。本质就是**状态机暂停 + 快照已落盘 + 恢复时从快照重建**。这三件事凑齐，HITL 就成立了。

> 2026-10-16 更新：以上是"状态层"讲法；执行层的完整语义（审批单登记 → 任务线程 park 在
> [ApprovalGate](../src/main/java/com/xb/agent/state/ApprovalGate.java) → confirm/abort 唤醒 → 超时收敛）
> 与配套的异步执行模型，详见 [09 · 流式、HITL 与可观测](/09-流式与HITL与可观测)。
> 关键时序：**先登记审批单，再流转状态**——反了就会出现审批请求抢先到达、白等到超时的竞态。

## 踩坑：Statemachine 4.x 的响应式 API

`sendEvent` 在 4.x 返回 `Flux<StateMachineEventResult>`，且状态机本身是内存态，重启即丢。所以 [TaskRunner](../src/main/java/com/xb/agent/state/TaskRunner.java) 最终用**自己的流转表 + 快照落盘**实现，StateMachineConfig 保留展示 DSL。教训：框架的状态机和"我要的持久化状态机"是两回事，快照才是 source of truth。
